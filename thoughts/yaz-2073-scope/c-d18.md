## 🔒 D18 resolved: which upstream Excalidraw perf fixes go into the fork

The audit is done: `$SCRATCH/findings/engine-upstream-perf.md`. The fork is based on upstream `1acf66ed` (#11777, 2026-07-28) and is 55 commits behind master.

- **Already in the fork:** #8697, #10578, #10648, #8980 and #9352, plus about 20 other upstream perf commits.
  - #10578 is already how dark mode renders here, so there's nothing to change.
- **Taking:**
  - **#12180 (resize).** At 4k elements, the bound-element update on resize goes from 503 ms to 0.2 ms. No visual change.
  - **#12183 (drag).** At 4k elements, a drag step goes from 525 ms to 6.5 ms. No visual change. One import conflict, resolved.
- **Conditional:** #12050 (dark-mode interactive canvas). Upstream it changes some dark-mode colors: smart-shape handles, the lasso trail and the text-selection highlight. A fixup keeps them identical to within 1/255.
  - We take it **only if** it measurably helps in Electron: dark-mode drag or marquee p95 frame time must improve by ≥20%.
  - It must also pass a pixel diff with no visible change.
  - Otherwise it's left out, with the numbers recorded on 5A.
- **Declined:** #12063. It's a crispness fix with a sub-pixel rendering shift (≤0.5 device px): a visual change, and not a speed fix.
- **Process:**
  - Fork changes are committed on branch `yaz-2073-perf` in a separate fork worktree, then repacked into the app with `tools/packEngine.mjs`.
  - **The fork branch must be pushed to the fork's origin before the app merge.** That waits for Yasin's go, like every other push.
- **Pre-existing:** 11 fork vitest failures on the base (10 in `worker/imageStudio.test.ts`). They're unrelated and tracked in 5A's comments.
